    Renderers

    When you import a PBR asset, JElib builds a complete, wired material for your active renderer — every map connected to the right input, in the right color space, ready to render. No manual shader work.

    The three renderers

    JElib supports Redshift, Octane, and Karma, in both the OBJ//mat and LOP/Solaris contexts. Pick your engine with the toolbar renderer selector — your choice is remembered across sessions.

    In Solaris, JElib builds inside a materiallibrary and wires the assignment for you; in OBJ it builds a native material container and assigns it via a Material SOP.

    If a renderer isn't installed

    If the chosen renderer's plugin isn't loaded, JElib skips the material and still loads the geometry — no broken nodes. Switch the selector to a renderer you have installed and re-import to get the shader.

    The material it builds

    By default JElib builds each renderer's standard surface. Switch Preferences → Import → Material Type to Open PBR for the OpenPBR surface instead:

    Renderer Standard Open PBR
    Redshift redshift::StandardMaterial redshift::OpenPBRMaterial
    Octane Standard Surface Open PBR Surface
    Karma mtlxstandard_surface mtlxopen_pbr_surface

    What gets wired

    For a full PBR set, JElib connects the maps it finds:

    • Base color, roughness, metalness, specular, opacity, emission
    • Normal / bump / height (see below)
    • Sheen, coat, anisotropy, translucency / SSS when present — a translucency map even switches on subsurface automatically

    Color space is handled for you: color maps as sRGB, data maps (roughness, metal, normal, height) as raw. Packed maps (ORM-style occlusion/roughness/translucency) are split to the right inputs, and a glossiness map is inverted into roughness when no roughness map exists.

    AO maps aren't connected

    Ambient-occlusion maps are not wired — the standard surfaces have no AO input. Composite AO into your base color beforehand if you need it.

    Normal, bump & displacement

    Preferences → Import → Bump Map Mode decides how surface detail is wired:

    • Normal Map (default) — use the normal map; fall back to a bump/height map only when there's no normal map.
    • Bump Map — prefer a dedicated bump map over the normal map.
    • Displacement — route the height map through the renderer's displacement output instead of bump.

    Each renderer uses its native nodes for this (Redshift BumpMap/Displacement, Karma mtlxnormalmap/mtlxdisplacement, Octane's normal/bump/displacement slots), and respects a normal-strength value if the set ships one.

    UV or triplanar

    Preferences → Import → Default Projection:

    • UV — standard UV sampling, with shared Scale / Offset / Rotate controls on the material.
    • Triplanar — world-space projection, no UV unwrap needed. A triplanar node is inserted per texture; the Scale/Offset/Rotate controls don't apply.

    You can also override projection per import in the preview panel.

    Where the material lives & how it's assigned

    Preferences → Import → Material Network controls where the material is built. The default, Current Network, follows the viewer — it builds a per-asset matnet in whatever network you're looking at (or directly inside a matnet/vopnet you're already in), falling back to /mat in a non-material context. The fixed overrides are a per-asset matnet inside the geo network (SOP Context), a shared /mat (Global), or a shared /obj/matnet (OBJ Context).

    In OBJ/SOP, a Material SOP assigns the material by shop_materialpath (or by name attribute — see Material Assignment). In Solaris, a materiallibrary → assignmaterial chain does it. Either way JElib also adds viewport-preview textures so the asset shows shaded before you render.
